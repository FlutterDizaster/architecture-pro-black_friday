# pymongo-api

Проектная работа спринта 4: стенд онлайн-магазина «Мобильный мир» с шардированием и репликацией MongoDB и кешем в Redis.

## Что где лежит

- `sharding-repl-cache`: итоговый стенд (задания 2, 3 и 4), проверять нужно его
- `mongo-sharding`: стенд только с шардированием (задание 2)
- `mongo-sharding-repl`: шардирование и репликация (задание 3)
- `schema.drawio`: схемы (задания 1, 5 и 6), пять страниц по шагам. Итоговая схема на последней странице «5. CDN (итоговая схема)»
- `architecture.md`: архитектурный документ (задания 7–10): шард-ключи коллекций, горячие шарды, чтение с реплик, миграция на Cassandra
- `compose.yaml`, `api_app`, `scripts`: исходный стенд из шаблона, не менялся

## Как запустить

```shell
cd sharding-repl-cache
docker compose up -d
./scripts/mongo-init.sh
```

Скрипт инициализирует сервер конфигурации и группы репликации, подключает шарды к роутеру, включает шардирование коллекции `somedb.helloDoc` и записывает в неё 1000 документов. Выполняется меньше минуты, в конце печатает число документов и реплики по шардам. Запускать его нужно один раз на свежих томах: повторный запуск допишет ещё 1000 документов.

Все сервисы должны быть в статусе `Up`:

```shell
docker compose ps
```

## Как проверить

Откройте http://localhost:8080. Приложение отдаёт JSON:

- `collections.helloDoc.documents_count`: общее число документов, 1000
- `shards`: два шарда, у каждого три реплики
- `cache_enabled`: должно быть `true`

Число документов на каждом шарде и состояние реплик:

```shell
./scripts/count-docs.sh
```

Кеширование: повторные запросы к `/helloDoc/users` выполняются быстрее 100 мс.

```shell
for i in 1 2 3; do curl -o /dev/null -s -w "%{time_total}s\n" http://localhost:8080/helloDoc/users; done
```

Остановить стенд и удалить тома:

```shell
docker compose down -v
```
